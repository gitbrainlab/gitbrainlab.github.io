# Migration to the second experimental candidate

The release bundle and adoption document advance to `0.1.0-rc.2`. The optional language profile is `civicspec-controlled-english/0.1-draft.3`. Historical ontology/mapping bytes and the original synthetic assertion fixture schema retain their versions. The evaluation ledger schema is separate from the production wire-contract work in R02.

Existing consumers pinned to rc.1 remain pinned to that release's original bytes. Consumers adopting rc.2 explicitly enable the language profile for a reviewed trial. Load the profile, requirements and runtime supplement from the same manifest. Do not combine the new prompt with an old guard or report the entire profile implemented when only the linter is present.

The candidate adds protected rewrite dimensions, requirement authoring conventions, diagnostic action recognizers and an evaluation harness. It does not assign canonical municipal IDs, resolve bodies, change legal-rule applicability, adopt an external license, or authorize production fact publication. Source-grounded evaluation annotations are candidate research interpretations.

For a wording-only operation, preserve the ledger's semantic fields. For an actual correction, create a new assertion version, retain previous evidence and reviews, and query downstream dependencies. Backfill only the source/body cohorts approved for the changed adapter or meaning rule. No blanket corpus rewrite is part of this release.

Before runtime adoption, validate your production schema, actor/capacity resolution, condition logic, exact selectors, multi-treatment splitting, prose fidelity and review policy. The reference classifier retains known errors on J021, J032 and J061; its label cannot approve a civic fact. The comparison of bot-farm model prompts remains specified but unexecuted.

Rollback returns new work to the previously approved compatible release and queues affected outputs for review. It does not delete history. Discovery remains a candidate channel; stable stays unset. Each bot's adoption requires a separate receipt.
